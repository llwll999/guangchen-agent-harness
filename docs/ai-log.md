# AI Prompt 与问题解决记录

日期：2026-10-03。本项目由 AI 辅助创建。下面记录真实需求、开发期间的工作约束与实际问题，不声称候选人已经独立掌握或运行了真实模型。运行和面试练习后，应追加自己的理解、修改与真实验收记录。

## 输入与工作提示

用户提供了飞书题目链接及招聘方说明：“请务必理解自己让AI写的代码，面试会针对代码细节展开，会一行行过代码。一周内完成即可。”

开发时采用的工作提示归纳如下（是过程摘要，不伪称为用户逐字发送的提示）：

1. 先读取完整原题，提取验收条件，禁止把猜测当题目。
2. 默认用 Python 做最小版本；主流程自行实现，不使用 Agent 框架。
3. 通过真实 Chat Completions function calling 接入模型；测试可用脚本响应，但生产不能用关键词选择工具。
4. 工具定义包含名称、描述和 Schema；实现 calculator、mock search 和 todo。
5. 用用户与窗口组合隔离会话；持续对话、工具追问、基础 context 压缩必须可测试。
6. 测试边界：错误参数、工具异常、模型失败、无限循环、重启、busy、长历史和超长结果。
7. 文档明确哪些是实现、哪些是架构建议、哪些尚未真实验证；提供代码讲解和面试反问。

生产 system prompt 的实际全文在 `mini_agent/context.py` 的 `SYSTEM` 常量中，可以直接阅读和修改。真实烟雾测试的用户提示全文保存在 `scripts/smoke_real.py` 中。

## 实际问题和修复

| 问题 | 处理与证据 |
| --- | --- |
| 普通网页工具无法读取飞书，正文按滚动位置加载 | 使用浏览器读取目录和各段正文，题目汇总到 requirements.md |
| Browser 读取超时 | 重新连接并读取已打开的同一文档，没有据空页面编写题目 |
| 工具调用与结果可能被历史裁剪分开 | 按 user 轮次分组保留；200 轮测试验证调用 ID 集合与结果 ID 集合一致 |
| 模型失败后前一步 todo 是否丢失 | 任务终止时保存已有本地工具结果，测试确认失败后待办存在且能继续 |
| Windows 测试清理失败，SQLite 文件仍被占用 | 初版误以为 connection 的 with 会关闭连接；改用 closing 显式关闭，测试恢复通过 |
| 非思考模式和 reasoning_content 协议不可混用 | 检查官方工具调用与思考模式文档；当前只支持非思考模式并明确拒绝额外推理字段 |
| 空 dict tool_calls 被 `or []` 当成无调用 | 改为仅 None 转空列表，其他结构严格检查；加协议反例 |
| 超长 todo list 可能撑爆上下文 | 初版用结果预览；审查发现精确读取困难，现改为带 next_offset 的预算分页，100 条特殊字符数据验证完整读取 |
| 当前环境没有 API 配置 | 不伪造真实调用通过记录；提供独立真实 API 烟雾脚本 |

API 协议依据：[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)，[思考模式回传要求](https://api-docs.deepseek.com/guides/thinking_mode/)。服务商额外字段和模型支持可能变化，应按自己实际账户验证。

## 2026-10-05 输入与认证排障

用户反馈：隐藏输入时无法确认密钥是否粘贴。查看实际截图和不含密钥的报告，首个聊天任务返回 HTTP 401，模型另有 deepsekk-flash 拼写错误。按 DeepSeek 官方错误码文档，401 为认证失败，不能仅修正模型名就宣称通过。

修复 Windows 入口为星号显示、字符计数、退格与清空；保护非 Windows getpass 不降级为明文输入。失败时保留 failed 状态并恢复环境，报告字段 planned_tasks 只表示计划数量。新增五项离线测试均通过，46 项总测试通过；Windows 交互测试使用占位值，不读取用户密钥。真实认证仍需用户本地重试。

参考：https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/ 。
